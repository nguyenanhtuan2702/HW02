# [FR-17] API mã giảm giá chấp nhận thiếu hoặc sai giá trị `type`

**Bug ID:** BR-FR17-01  
**Tiêu đề GitHub Issue:** `[FR-17] API mã giảm giá chấp nhận thiếu hoặc sai giá trị type`  
**Tính năng / ca kiểm thử:** FR-17 — TC17-05, TC17-06.  
**Mức độ nghiêm trọng:** Chưa đánh giá; tài liệu dự án không có thang phân loại mức độ nghiêm trọng.  
**Trạng thái xác minh:** Được xác nhận bằng phản hồi API và trace trong lượt thực thi `20261016-155435`; chưa chạy lại độc lập.  
**Tần suất:** Cả hai biến thể `type` không hợp lệ đều được chấp nhận một lần trong lượt chạy đã ghi nhận.  
**Môi trường:** Windows_NT 10.0.26300; Node.js v24.15.0; Admin `http://localhost:5174`; API `http://localhost:3000/api`.

## Mô tả

API tạo mã giảm giá vẫn tạo mã khi bỏ trường `type` hoặc đặt `type` thành `other`. FR-17 quy định `type` là trường bắt buộc và chỉ cho phép `percent` hoặc `fixed`.

## Điều kiện tiên quyết

- API quản trị khả dụng và yêu cầu sử dụng dữ liệu mã giảm giá hợp lệ, chưa bị trùng ở các trường còn lại.
- Phạm vi kiểm thử là API; nhật ký thực thi ghi chú rằng danh sách chọn trên giao diện có giá trị mặc định.

## Các bước tái hiện

1. Gửi yêu cầu tạo mã giảm giá hợp lệ nhưng bỏ trường `type` (TC17-05).
2. Gửi yêu cầu khác, các dữ liệu còn lại hợp lệ, với `type:"other"` (TC17-06).
3. Quan sát phản hồi và xác định mã giảm giá có được tạo hay không.

## Kết quả mong đợi

FR-17 yêu cầu phải có `type` và quy định các giá trị được phép là `percent` và `fixed`; mỗi dữ liệu nêu trên vi phạm yêu cầu này nên không được tạo mã giảm giá. Nguồn: [`eshop-sut/README.md`](../../eshop-sut/README.md), mục 6, FR-17, gạch đầu dòng về các trường bắt buộc. Đặc tả không quy định phản hồi lỗi cụ thể.

## Kết quả thực tế

Cả hai yêu cầu API đều trả về HTTP 200 cùng nội dung `{"message":"Coupon created","id":...}`.
